# PDFdir 整体产品复审与修复记录

## Product Read

- 用户：需要为本地 PDF 创建、校对或保留导航书签的普通桌面用户。
- 核心任务：选择 PDF → 获得可编辑目录 → 校对层级与页码 → 安全生成独立输出 PDF。
- 风险画像：操作风险 7、任务频率 4、信息密度 6、视觉表达 3、动效 1。
- 视觉方向：沿用 AgentEnv Manager 的系统字体、白色工作面、细边界、紧凑工具栏和单一蓝色主操作；单任务界面不引入侧栏。
- 明确避免：草稿静默丢失、页码偏移错误、有损 PDF 降级、后台任务使用过期快照、无效输入仍可生成、伪装成可发布的未签名安装包。

## 主要发现与处理

| 严重度 | 发现 | 处理 |
| --- | --- | --- |
| P0 | 自动页差在 GUI 再减 1，所有推导页码错一页 | 直接采用领域层返回值，并增加 GUI 映射回归测试 |
| P0 | 同一 PDF 的旧识别结果可覆盖用户刚编辑的草稿 | 任务上下文记录起始草稿，文档或草稿变化时丢弃旧结果 |
| P0 | PDF 复制会丢附件等文档级目录结构，失败后还会降级到丢注释的页复制 | 改为完整克隆文档 catalog，删除有损 fallback；生成后校验附件名称、内容哈希、页数和书签语义 |
| P0 | 各平台 tag workflow 可提前公开不完整 Release，且版本注入错误 | 改为单一跨平台 gate；四个平台先测试、烟测和上传 artifact，全部成功后才核对资产、生成校验和并公开；分页扫描并拒绝同 tag 的既有 draft/公开 Release |
| P1 | 切换文档、关闭窗口、导入已有书签缺少草稿边界 | 增加文档激活事务、切换/关闭确认、纯文本导入与 dirty/generated 基线 |
| P1 | 预览宣称可编辑/拖动但运行时不支持，重建还会静默覆盖修正 | 实现 F2、双击、拖动、Delete、键盘菜单、完整值 tooltip；重建前后给出明确状态 |
| P1 | 无效正则、空标题、非整数页码仍允许生成 | 设置内联错误、错误控件标识、预览验证和生成禁用 |
| P1 | 生成期间源路径、目录和规则仍可变更 | 写入任务冻结快照控件，隐藏旧主操作并让“取消任务”成为当前操作 |
| P1 | 指纹检查与 `os.replace` 之间仍可能覆盖并发创建的文件 | 取消覆盖路径：已有输出自动选择 `_new_2` 等编号；最终用原子 create-if-absent 提交，目标被抢占即失败 |
| P1 | 持久化只验证页数 | 同时验证新书签标题、层级和页目标；保留模式还验证原 outline |
| P1 | 更新检查按字符串比较且阻塞 GUI，网络失败显示“最新” | 使用 `packaging.version.Version`、错误三态和独立后台线程 |
| P1 | Cocoa 键盘焦点不可见、编辑器形成 Tab 死区、Esc 快捷键重复绑定、设置弹窗焦点链中断 | 增加焦点态、Ctrl+Tab 离开编辑器；Esc 仅保留一个任务级入口；设置页建立可预测的 Tab/Shift+Tab 链 |
| P1 | 200% 字号时核心编辑区缩为 0、工具和设置项裁切 | 大字号动态最小窗口为 900×700，核心视图保留多行高度；工具区换行，正则规则改单列，设置页同步扩大 |
| P1 | 长文件名在工作态被单行裁切，用户无法同时确认源文件与输出目标 | 状态改为“源文件 → 输出文件”两行结构，各行独立中间省略并保留完整 tooltip 与无障碍描述；补测普通和 24pt 工作态 |
| P1 | macOS 发布没有签名、公证、Gatekeeper 门槛，预发布 tag 还会写入非法 bundle 短版本 | 强制 Apple 凭据与完整门禁；短版本规范成三段数字、build 使用纯数字 run number，格式不合规即停止 |
| P2 | 文本目录识别先读取全书再截前 30 页 | 文本提取支持 `max_pages` 与逐页取消，TOC 真正止于前 30 页 |
| P2 | 启动目录中的无关 `config.ini` 可导致崩溃 | 删除 cwd 配置读取，首次目录改为用户 Documents/Home |

## 产品边界

- 预编译包不捆绑 PaddleOCR/Tesseract 模型与系统运行时；文字层识别、手工目录和书签生成保留。扫描版自动识别需要源码安装 OCR 可选依赖，UI 与 README 会给出可执行说明。
- macOS 本地验证只能完成 ad-hoc 重签、严格签名结构校验和冻结包烟测；Developer ID 公证必须在带 Apple 凭据的 tag workflow 中完成。
- 现有桌面 E2E 是真实 Qt 事件循环中的产品集成旅程，系统文件选择器使用可控替身；最终冻结包另由 `--smoke-test` 验证 GUI 到 PDF 的生成路径。

## 最终验证

- Python 3.12.11 与 3.9.6：各 123 项全量测试通过。
- 原生 Cocoa：47 项 GUI 与桌面 E2E 测试通过；源码 `--smoke-test` 通过。
- 冻结应用：从最终代码重新构建 arm64 `.app`，隔离 `HOME`/`PATH` 后分别以 offscreen 与 Cocoa 完成 GUI → PDF → 书签烟测。
- macOS 本地产物：bundle id `com.chroming.pdfdir`、短版本 `0.3.0`、build `1`；ad-hoc 严格签名结构验证通过。Developer ID、公证与 Gatekeeper 仍由真实 tag workflow 验证。
- Release：YAML 解析、既有 draft/公开 Release 门禁、资产集合与不覆盖契约均有自动化测试；本次没有创建或发布真实 Release。
